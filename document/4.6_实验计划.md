# 4.6 消融实验与实时性分析实验计划与使用步骤

本计划用于完成第四章 4.6 节“消融实验与实时性分析”。4.6 不再重新录制真实机器人数据，而是复用 4.3 的动态障碍物预警结果和 4.5 的虚拟闭环安全运动日志，分别回答两个问题：

1. 去掉时空风险预测、构型相关排斥向量、速度级安全滤波后，系统性能会如何变化；
2. 当前离线/虚拟闭环实现中的控制生成耗时是否满足实时运行需求，以及现有 timing 日志是否足以支撑完整端到端实时性结论。

本节已新增并完善以下程序：

| 文件 | 作用 |
| --- | --- |
| `experiments/exp_46_ablation.py` | 从 4.3 和 4.5 结果聚合消融表 |
| `experiments/exp_46_timing.py` | 从 4.5 trial 日志聚合模块耗时、端到端频率和控制频率 |
| `experiments/exp_46_main.py` | 一键生成 4.6 消融表、实时性表和数据合理性检查报告 |

## 1. 实验总体设计

4.6 的消融版本与前文实验方法的对应关系如下。

| 4.6 消融版本 | 预警指标来源 | 闭环指标来源 | 目的 |
| --- | --- | --- | --- |
| Full | 4.3 `ours` | 4.5 `ours_full` | 完整方法 |
| w/o Temporal Risk | 4.3 `ours_wo_temporal` | 复用 4.5 `ours_full` | 只观察去掉时空预测后的提前预警变化 |
| w/o Repulsive Vector | 4.3 `ours` | 4.5 `ours_scale` | 观察去掉构型相关排斥向量后的最小距离和违规时间变化 |
| w/o Safety Filter | 4.3 `ours` | 4.5 `ours_rep` | 观察去掉速度级安全滤波后的安全裕度变化 |

说明：

- `w/o Temporal Risk` 只改变预警模块，因此闭环运动指标复用 Full；
- `w/o Repulsive Vector` 保留速度缩放但去掉主动排斥；
- `w/o Safety Filter` 保留速度缩放和排斥向量，但不做速度级安全投影；
- 4.5 优先使用 `data/results/ch4_5_virtual`，因为该目录来自虚拟闭环积分，会重新计算 `D_ref(q_sim,t)`，不同控制器之间的距离指标有可解释差异。

## 2. 评价指标

### 2.1 消融指标

| 指标 | 含义 | 趋势 |
| --- | --- | --- |
| `T_lead` | 提前预警时间，来自 4.3 动态障碍物预警实验 | 越大越好 |
| `D_min_ref` | 虚拟闭环过程中最小参考距离 | 越大越安全 |
| `T_viol` | `D_ref < d_stop` 的累计时间 | 越小越好 |
| `R_avoid` | 满足安全距离、未超时且末端误差合格的 trial 比例 | 越大越好 |
| `R_timeout` | 任务超时比例 | 越小越好 |
| `J_q_rms` | 指令关节速度差分 RMS，反映运动平滑性 | 越小越平滑 |

### 2.2 实时性指标

| 指标 | 含义 |
| --- | --- |
| `T_pre_ms` | 点云预处理耗时 |
| `T_dec_ms` | 自身点云解耦耗时 |
| `T_obj_ms` | 对象聚类与建模耗时 |
| `T_trk_ms` | 对象关联与速度估计耗时 |
| `T_risk_ms` | 时空风险预测耗时 |
| `T_rep_ms` | 排斥向量/控制器内部计算耗时 |
| `T_cmd_ms` | 速度指令生成耗时 |
| `T_frame_ms` | 当前日志记录到的单帧总耗时 |

当前 4.5 日志中，`T_pre_ms`、`T_dec_ms`、`T_obj_ms`、`T_trk_ms`、`T_risk_ms` 尚未在真实感知链路中埋点，因此为 `0`。本次 4.6 实时性结果只能作为“虚拟闭环控制生成段耗时”证据，不能直接作为完整 RGB-D 感知到控制输出的端到端耗时结论。

### 步骤 4：消融实验结果

表 4-7 消融结果如下。

| 版本 | T_lead↑ | D_min_ref↑ | T_viol↓ | R_avoid↑ | R_timeout↓ | J_q_rms↓ |
| --- | --- | --- | --- | --- | --- | --- |
| Full | 5.1286 | 0.1968 | 0.0000 | 1.0000 | 0.0000 | 0.4109 |
| w/o Temporal Risk | 4.7356 | 0.1968 | 0.0000 | 1.0000 | 0.0000 | 0.4109 |
| w/o Repulsive Vector | 5.1286 | 0.0561 | 0.4317 | 0.5000 | 0.0000 | 0.2152 |
| w/o Safety Filter | 5.1286 | 0.1041 | 0.0000 | 1.0000 | 0.0000 | 0.3715 |

结果解释：

- 去掉时空风险预测后，`T_lead` 从 `5.1286 s` 降到 `4.7356 s`，提前量减少约 `0.3929 s`，说明动态预测确实带来更早预警；
- 去掉排斥向量后，`D_min_ref` 从 `0.1968 m` 降到 `0.0561 m`，且 `T_viol` 增至 `0.4317 s`，`R_avoid` 降为 `0.5`，说明仅靠速度缩放不足以在虚拟闭环中保持足够安全裕度；
- 去掉速度级安全滤波后，`D_min_ref` 为 `0.1041 m`，低于 Full 的 `0.1968 m`，但未出现 `d_stop` 违规，说明排斥向量已经提供主要避让能力，安全滤波进一步扩大了距离裕度；
- Full 的 `J_q_rms` 高于无排斥版本，这是主动避让引入额外关节速度变化的代价，和 4.5 结果趋势一致。

结论：表 4-7 数据趋势合理，可用于 4.6 消融分析。

表 4-9 端到端与控制频率如下。

| 指标 | 数值 |
| --- | --- |

结果解释：

- 现有 timing 日志中只有 `T_rep_ms`、`T_cmd_ms` 和 `T_frame_ms` 为非零，说明 4.5 虚拟闭环日志只测量了控制器 `step()` 调用耗时；
- `T_cmd_ms` 平均为 `40.8883 ms`，对应平均控制生成频率约 `24.46 Hz`；
- `T_cmd^95 = 199.8850 ms`，明显高于 `20 ms` 控制循环目标，说明当前 Python 离线有限差分/表面距离实现仍有优化空间；
- 由于感知预处理、解耦、对象建模、跟踪和预测模块没有真实计时，`T_e2e^95` 不应作为完整系统端到端延迟使用。

结论：本次实时性数据可用于说明“当前离线 Python 控制生成实现的耗时瓶颈”，但不可用于证明完整在线感知-控制链路满足实时性。若论文需要完整实时性表，应在 4.3/4.5 在线处理循环中补充真实模块埋点后重新统计。
