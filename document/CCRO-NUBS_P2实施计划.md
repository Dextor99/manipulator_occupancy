# CCRO-NUBS P2：NUBS 总时长与分段时间联合优化实施计划

> 目标：将阶段 1–4 的固定分段时间轨迹扩展为可优化物理时间的 NUBS，并形成可复现的梯度、约束与性能证据。本阶段只做仿真/数学后端验证，不连接真实机械臂。

## 1. 实施范围

P2 分两级执行：

1. `total`：保持初始分段比例不变，联合优化中间插值构型和总时长；
2. `segment`：联合优化中间插值构型和每一段物理时长。

优化变量采用时间对数参数化，确保每段时长严格为正。总时长模式施加 `[3, 10] s` 硬边界；分段模式施加 `[0.35, 3.5] s` 硬边界。目标函数为

```text
J = lambda_smooth * integral ||jerk||^2 dt
  + lambda_time * sum(T_i)
  + joint-limit penalties
```

边界 `q/qd/qdd` 与中间插值条件仍由 NUBS 构造硬满足，不变成软罚项。

## 2. 程序设计

- `planning/time_optimizer.py`：总时间/分段时间统一优化器；
- `config/ccro_p2.yaml`：时间权重、边界与验收阈值；
- `experiments/exp_ccro_p2.py`：固定时间、总时间和分段时间三组自动对比；
- `tests/planning/test_ccro_p2.py`：参数化、梯度和优化回归测试；
- `scripts/setup_ccro_p2.sh`：py310 环境构建、测试、实验一键执行。

点梯度与时长梯度来自 C++ NUBS 完整能量梯度；通过链式法则映射到 `log(T)`。限位罚项仅在实际激活时使用中心差分，避免无约束轨迹承担无意义计算开销。

## 3. 实验与指标

三种方法使用完全一致的起终状态、分段数、关节限位和线性初始插值点：

| 方法 | 可优化变量 | 作用 |
|---|---|---|
| fixed | 中间构型 | 阶段 1 基线 |
| total | 中间构型 + 总时长 | 验证速度—平滑度权衡 |
| segment | 中间构型 + 每段时长 | 验证非均匀时间分配 |

记录：总时长、各段时长、jerk 能量、完整目标值、边界/路点误差、关节限位、迭代次数与耗时。

## 4. 验收条件

```text
总时间与分段时间完整梯度相对误差 <= 2e-3
q/qd/qdd 边界误差 <= 1e-5
中间插值误差 <= 1e-7
关节位置/速度/加速度超限 <= 1e-8
两种时间优化最终目标均低于各自初始目标
优化器正常收敛且结果有限
```

## 5. 运行方法

```bash
bash scripts/setup_ccro_p2.sh
```

输出位于 `data/results/ccro_p2/`：`metrics.json`、`table_p2.md`、`config.yaml` 和轨迹对比图。真机阶段只需在验证制造商速度/加速度/jerk 上限并加入执行 watchdog 后使用保存的轨迹；P2 不自动下发运动指令。

## 6. 风险与后续接口

- `lambda_time` 决定“更快”与“更平滑”的 Pareto 位置，论文正式实验应在 P4 做权重扫描，不能只报告单点；
- 当前分段模式对每段独立加硬边界，后续动态风险目标须使用同一物理时间轴重新采样预测占据；
- 真机必须额外加入 jerk/torque 厂商约束、自碰撞和控制周期复核。
