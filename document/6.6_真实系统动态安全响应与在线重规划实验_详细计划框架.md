## 6.6.1 真实动态障碍安全响应回放实验

### 1. 实验目的

验证真实 RGB-D 采集序列中，系统能否对动态障碍物提前触发风险响应，并在障碍离开后恢复。

复用来源：

```text

data/results/ch6_2_real/table_6_2_real_warning.md
```

第六章 6.6 汇总命令：

```bash
PYTHON_BIN=/home/hzy/miniconda3/envs/py310/bin/python \
  bash scripts/setup_ch6_6.sh
```

输出：

```text
data/results/ch6_6/table_6_6_real_dynamic_response.md
```

### 2. 当前结果

| 场景 | trial 数 | `T_lead` / s | `R_miss` | `R_false_time` | `D_trigger_ref` / m | `T_recover` / s |
|---|---:|---:|---:|---:|---:|---:|
| static_safe | 1 | - | - | `0.0100` | `0.2075` | - |
| dynamic_approach | 8 | `5.1286` | `0` | `0.4482` | `0.3551` | `0.8488` |
| recover | 3 | `1.2808` | `0` | `0.0950` | `0.2376` | `0.3732` |

论文可写结论：

```text
真实动态靠近场景中，本文方法在 8 条 trial 上无漏检，平均提前量约 5.13 s；
approach-hold-leave 场景中，系统能够在障碍离开后恢复，平均恢复时间约 0.37 s；
static_safe 中误触发时间比例约 1%，说明真实点云噪声下仍存在少量保守触发，应在论文中作为实际系统现象说明。
```

## 6.6.2 真实中间连杆风险识别与安全响应

### 1. 实验目的

验证真实采集序列中，中间连杆风险不是末端距离可以替代的；系统应能识别 upperArm、foreArm、wrist 等非末端风险。

复用来源：

```text
data/results/ch6_3_real/metrics.json
data/results/ch6_6/table_6_6_real_body_risk.md
```

### 2. 当前结果

| 场景 | trial 数 | sampled | ee-risk | body-risk | `C_grad_D` | `R_body` | top links |
|---|---:|---:|---:|---:|---:|---:|---|
| ee_risk | 8 | 140 | 27 | 0 | `0.9939` | - | left_link, gripper_base_link, upperArm_Link |
| body_risk | 3 | 185 | 0 | 118 | `0.9968` | `0.9606` | wrist1_Link, upperArm_Link, wrist2_Link |

论文可写结论：

```text
真实中间连杆场景中，118/185 个采样帧属于 body-risk；
最近风险连杆主要集中在 wrist1_Link 和 upperArm_Link；
本文全身风险方法在 body-risk 场景中的 R_body=0.9606，而仅末端方法在 6.3 中为 0；
这说明真实系统中必须使用构型耦合全身风险，而不能只用末端安全距离。
```

### 2. 真实在线重规划补充实验步骤

#### Step 1：实机安全准备

```text
1. 确认急停按钮可用；
2. 设置机械臂低速模式，最大关节速度 ≤ 0.10 rad/s；
3. 设置最大关节加速度 ≤ 0.20 rad/s^2；
4. 确认操作者站在安全区域；
5. 使用轻质泡沫/纸板作为障碍物；
6. 禁止使用硬质或尖锐物体作为动态障碍。
```

#### Step 2：软件门控检查

逐项更新 `config/ccro_p7.yaml`：

```text
self_collision_ok: true
watchdog_ok: true
communication_ok: true
timestamp_ok: true
switch_state_error_ok: true
emergency_stop_ok: true
manufacturer_limits_verified: true
allow_real_robot_commands: true
```

只在全部检查通过后执行：

```bash
PYTHON_BIN=/home/hzy/miniconda3/envs/py310/bin/python \
  python -m experiments.exp_ccro_p7_dry_run
```

#### Step 3：shadow 模式

```text
1. 机械臂保持静止或执行极低速标称轨迹；
2. 系统读取真实 q/qdot 和 RGB-D；
3. 运行感知—风险—NUBS 重规划；
4. 只记录候选轨迹，不发送切换命令；
5. 确认候选轨迹 dense validation 全部通过。
```

记录指标：

```text
T_trigger_real
T_replan_real
candidate_min_distance
candidate_goal_error
candidate_accepted
rejection_reason
```

#### Step 4：低速安全层闭环

```text
1. 只允许速度缩放/暂停，不允许轨迹切换；
2. 动态障碍从侧方缓慢靠近；
3. 验证 D_min ≤ d_stop 时机械臂进入 hold；
4. 障碍离开后验证速度平滑恢复。
```

#### Step 5：低速在线切换闭环

```text
1. 使用已通过 shadow 的场景；
2. 初始 NUBS 轨迹低速执行；
3. 动态障碍进入预测风险区；
4. 触发局部 CCRO-NUBS 重规划；
5. 候选轨迹通过 dense verifier；
6. 在 q/qd 切换误差阈值内切换轨迹；
7. 记录 D_min 曲线、切换时刻和任务完成误差。
```

停止条件：

```text
任一 watchdog 超时；
候选轨迹 dense D_min < d_stop；
q 切换误差 > 0.02 rad；
qd 切换误差 > 0.05 rad/s；
相机时间戳异常；
操作者触发急停。
```
