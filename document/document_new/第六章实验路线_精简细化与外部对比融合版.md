# 第六章实验路线：精简细化与外部对比文献融合版

> 本文件由“精简细化版”和“外部对比文献标注版”融合而成。核心原则是：**不增加实验数量，而是把少数必要实验的实施过程、外部对比方法、文献来源、记录指标和论文呈现方式统一整理清楚**。
>
> 第六章最终正文不需要展示所有实验日志和中间结果，只保留能够支撑主线结论的核心图表。内部变体只用于消融实验，主要对比实验尽量采用已发表论文或成熟工程框架中的代表性方法。

## 一、总体实验主线

第六章不应写成工程测试清单，而应围绕论文主张形成一条清晰证据链：

```text
时空风险是否能提前发现动态障碍
→ 全身风险是否能发现末端/稀疏关键点方法漏检的问题
→ 风险约束 NUBS 是否能生成安全平滑轨迹
→ 动态障碍下滚动重规划是否能提高安全裕度
→ 真实 RGB-D 和低速实机链路是否可运行
→ 各模块贡献和计算边界是否清楚
```

因此，正式实验压缩为四组主实验和一组附属统计：

| 编号 | 实验组 | 主要作用 | 正文定位 | 是否新增大量实验 |
|---|---|---|---|---|
| E1 | 风险感知与全身风险评价 | 验证时空风险和机械臂全身风险的必要性 | 正文重点 | 否，沿用风险建模验证场景 |
| E2 | 静态障碍轨迹规划 benchmark | 与经典规划/优化方法对比，验证风险约束 NUBS 的安全性和平滑性 | 正文重点 | 否，只规范对比方法 |
| E3 | 动态障碍虚拟闭环与滚动重规划 | 与速度缩放、APF、MPC/APF、RRT 局部重规划等已有方法对比 | 正文最核心 | 否，沿用动态虚拟闭环场景 |
| E4 | 真实 RGB-D 与低速系统验证 | 验证真实感知—风险—验收—低速执行链路 | 正文重点，但不过度展开 | 否，不强行复现所有外部算法 |
| E5 | 消融与耗时分析 | 说明本文内部模块贡献和系统瓶颈 | 附属统计 | 否，复用 E1–E4 数据 |

不再单独设置大量独立实验，例如单独的点云分割大对比、单独的 NUBS 数值正确性大实验、单独的所有规划器排名实验、单独的完整真实动态抓取实验等。若确有需要，这些只作为调试记录、附录材料或补充材料，不作为正文主线。

## 二、实验前统一设置

### 2.1 固定实验平台与参数

正式跑实验前，先冻结以下内容，后续所有结果均使用同一套配置。这样可以避免不同实验之间因为参数变化导致结果不可比。

| 类别 | 需要固定的内容 |
|---|---|
| 机械臂模型 | AUBO i16 或当前实际使用机械臂的 URDF/Mesh 模型；关节限位、速度限位、加速度限位 |
| 传感器 | RealSense D435i 或当前 RGB-D 相机；内参、深度尺度和采样频率 |
| 坐标系 | 相机坐标系、机器人基坐标系、世界坐标系外参固定 |
| 点云处理 | 工作空间裁剪范围、voxel size、自滤除阈值、离群点滤波参数 |
| 对象提取 | DBSCAN 或聚类方法参数、对象关联阈值、速度平滑系数 |
| 风险参数 | 安全影响距离、停止距离、预测时域、预测步长、风险膨胀系数 |
| NUBS 参数 | 阶次、节点数、轨迹时长、时间分配、优化迭代上限、终止阈值 |
| 验收参数 | dense safety check 点数、最小安全距离阈值、终端误差阈值、关节约束阈值 |
| 实机速度 | 低速比例、最大关节速度、速度缩放策略、急停条件 |

### 2.2 统一记录格式

每次实验都保存以下文件，便于后续自动统计：

```text
config.yaml               # 本次实验配置
scene_config.yaml         # 场景、障碍物、起终点设置
trajectory.csv            # t, q, dq, ddq
obstacle_log.csv          # 障碍物中心、半径、速度、类别、置信状态
risk_log.csv              # D_min, R_body, active_link, active_points, trigger_state
planner_log.csv           # success, accepted, J_risk, J_smooth, goal_error, plan_time
runtime_log.csv           # 感知、风险、优化、验收、控制输出各模块耗时
figures/                  # 轨迹图、风险曲线、可视化截图
videos/                   # 关键实验录屏或真实实验视频
```

正式论文正文只使用统计后的表格和少量代表性图，不展示全部日志。

# E1 风险感知与全身风险评价实验

## E1.1 实验目的

E1 不再把 `EEF-only`、`Body-current` 作为主要外部对比，而是将其归入辅助分析或 E5 消融。E1 主要回答三个问题：

1. **对象级时空风险是否比当前帧占据或普通体素占据更适合动态障碍预警？**
2. **Mesh 全身风险是否比少量 critical points/APF 风险更能覆盖机械臂中间连杆、腕部和夹爪等非末端风险？**
3. **在真实 RGB-D 点云下，本文方法能否完成外部障碍物保留和全身风险响应？**

E1 不写成完整点云分割 benchmark。点云处理只是风险模型输入链路，不单独展开大规模算法比较。

## E1.2 对比方法

| 方法 | 文献/来源 | 实施方式 | 对比重点 |
|---|---|---|---|
| Current-frame occupancy | 常规点云聚类/当前帧占据 | 只用当前帧障碍物中心与包围体，不预测未来位置 | 是否缺乏动态风险提前量 |
| OctoMap-like occupancy | Hornung et al., 2013 | 将点云投影为体素占据或近似体素网格，不做对象级速度预测 | 与对象级时空预测相比是否更滞后或更保守 |
| Critical-point APF risk | Zhu et al., 2024；Khatib, 1986 | 在机械臂若干关键点或连杆代表点上计算障碍距离/APF 代价 | 是否漏检非关键点区域或 Mesh 表面局部风险 |
| Ours CCRO risk | 本文方法 | 对象级时空预测 + 全身 Mesh 表面采样风险 | 检测率、提前量、全身覆盖能力 |

## E1.3 场景设计

| 场景 | 设置 | 主要验证点 |
|---|---|---|
| R1 末端近场 | 障碍物靠近末端执行器附近 | 所有方法应基本可检测 |
| R2 中间连杆近场 | 障碍物靠近大臂、小臂或肘部 | critical-point 稀疏采样可能漏检，Mesh 全身风险应更稳定 |
| R3 动态横穿 | 障碍物横穿未来轨迹区域 | 时空风险应比 current-frame 更早触发 |
| R4 动态接近 | 障碍物从远处接近机械臂本体 | 比较风险提前量和误触发比例 |

建议每个场景 10–20 次，不再额外扩展更多场景。真实 RGB-D 只选择 R2 和 R4 做代表性序列即可。

## E1.4 实验步骤

1. 固定机械臂起始构型和目标构型，生成一条参考轨迹或固定若干代表构型。
2. 在仿真中放置障碍物，记录障碍物位置、速度、半径和真实最近距离。
3. 分别运行 Current-frame occupancy、OctoMap-like occupancy、Critical-point APF risk 和 Ours CCRO risk。
4. 对每个时间步记录障碍物估计、风险值、最小距离、触发状态、最近风险部位。
5. 对 R3/R4 计算风险提前量，即风险首次触发时刻相对于实际进入安全距离时刻的时间差。
6. 在真实 RGB-D 场景中复现 R2/R4，记录点云、外部对象、风险激活区域和触发状态。

## E1.5 记录指标

| 指标 | 含义 |
|---|---|
| detection rate | 风险检测率 |
| false trigger rate | 误触发时间比例 |
| T_lead | 动态风险提前量 |
| D_min | 最小安全距离 |
| active link / active surface points | 风险激活连杆和 Mesh 采样点数量 |
| T_risk | 单帧风险计算耗时 |

## E1.6 预期结果

| 方法 | 预期现象 |
|---|---|
| Current-frame occupancy | 对静态障碍有效，但对动态障碍预警滞后 |
| OctoMap-like occupancy | 适合静态建图，但对短时动态对象速度和未来占据表达不足 |
| Critical-point APF risk | 计算简单，但关键点稀疏时可能漏检 Mesh 表面或中间连杆风险 |
| Ours CCRO risk | 在中间连杆近场和动态未来风险场景中检测更充分，并具备更长风险提前量 |

如果 Ours 的误触发率高于 current-frame 方法，不应回避，可解释为时空预测以一定保守性换取提前预警。

## E1.8 支撑结论

```text
仅使用当前帧占据无法充分处理动态障碍；仅使用少量关键点或末端距离无法完整描述机械臂本体安全；本文构型耦合时空风险能够更早、更完整地发现潜在风险。
```

# E2 静态障碍轨迹规划 benchmark

## E2.1 实验目的

E2 用于与经典轨迹规划/轨迹优化方法对比，验证本文风险约束 NUBS 在静态障碍场景中的安全性和平滑性。核心问题包括：

1. 与采样式规划相比，本文方法是否能获得更平滑、dense safety check 更稳定的轨迹；
2. 与 CHOMP、TrajOpt、GPMP2 等轨迹优化方法相比，本文方法是否能体现全身风险约束的优势；
3. 与 MINCO-style 连续轨迹优化相比，本文方法不强调“全面优于 MINCO”，而是验证全身风险约束在 NUBS 滚动重规划框架中的作用。

## E2.2 对比方法

| 方法 | 文献来源 | 建议实现方式 | 说明 |
|---|---|---|---|
| RRT-Connect + smoothing/time parameterization | Kuffner and LaValle, 2000 | OMPL/MoveIt RRTConnect + shortcut + time parameterization | 采样式路径规划代表 |
| CHOMP | Zucker et al., 2013 | MoveIt CHOMP 或自有 CHOMP 接口 | 优化式轨迹规划代表 |
| TrajOpt | Schulman et al., 2014 | trajopt/tesseract-trajopt 或简化 SQP 版本 | 序列凸优化代表 |
| GPMP2 | Mukadam et al., 2018 | gpmp2 库或等价 Gaussian-process trajectory optimization | 连续时间优化代表 |
| MINCO-style / polynomial optimization | Wang/Zhou et al., 2022；Shao et al., 2023 | 最小控制努力多项式轨迹 + 同一风险验收 | 连续多项式基线 |
| Ours CCRO-NUBS | 本文方法 | 完整风险约束 NUBS | 本文方法 |

如果时间有限，优先完成 RRT-Connect、CHOMP/TrajOpt 二选一、GPMP2、Ours。MINCO-style 作为增强对比。

## E2.3 场景设计

| 场景 | 描述 | 目的 |
|---|---|---|
| P1 末端绕障 | 障碍物位于末端直线路径附近 | 验证基本绕障能力 |
| P2 中间连杆绕障 | 末端路径看似安全，但中间连杆可能碰撞 | 验证全身风险约束必要性 |
| P3 复杂近场/窄通道 | 多个障碍物限制机械臂本体空间 | 验证复杂场景安全裕度和耗时 |

建议每个场景 10–20 次随机扰动，不再扩大实验数量。扰动包括障碍物中心、半径、起点和终点小扰动。

## E2.4 统一实验协议

为保证公平，所有方法采用：

1. 相同机器人 URDF/Mesh；
2. 相同起终点构型；
3. 相同障碍物几何；
4. 相同关节位置、速度、加速度约束；
5. 相同 dense safety checker；
6. 相同最大规划时间预算；
7. 相同目标误差阈值和最小安全距离阈值。

对于 RRT-Connect，记录多随机种子结果；对于优化类方法，记录成功收敛和验收通过情况。所有方法最终都必须进入同一个 dense safety checker，不能只依赖各自规划器内部的碰撞检查。

## E2.5 实验步骤

1. 构造 P1/P2/P3 场景并保存为统一 `scene_config.yaml`。
2. 对每个场景生成 10–20 个扰动实例。
3. 对每个实例分别运行 RRT-Connect、CHOMP、TrajOpt、GPMP2、MINCO-style 和 Ours。
4. 对每条输出轨迹进行统一重采样，计算位置、速度、加速度和 jerk。
5. 对所有轨迹执行 dense safety check，记录是否 `accepted`。
6. 统计每种方法的成功率、验收通过率、最小安全距离、平滑性和耗时。

## E2.6 记录指标

| 指标 | 含义 |
|---|---|
| success rate | 规划器是否找到轨迹 |
| accepted rate | 是否通过统一 dense safety check |
| D_min | 轨迹最小安全距离 |
| J_risk | 轨迹风险积分 |
| J_smooth / jerk energy / roughness | 平滑性 |
| T_plan | 规划耗时 |
| goal error | 终端误差 |
| max velocity / acceleration violation | 运动约束违反量 |

## E2.7 预期结果

| 方法 | 预期现象 |
|---|---|
| RRT-Connect + smoothing | 通常能找到可行路径，但平滑性、轨迹稳定性和 dense safety check 通过率可能存在波动 |
| CHOMP / TrajOpt / GPMP2 | 是较强优化基线，但在全身 Mesh 风险和复杂近场下，结果依赖初始化、采样密度和碰撞代价设置 |

| Ours CCRO-NUBS | 优势在于对象级风险、全身 Mesh 风险和 NUBS 候选轨迹优化的统一，以及对后续滚动重规划接口友好 |

# E3 动态障碍虚拟闭环与滚动重规划实验

## E3.1 实验目的

E3 是第六章最核心的动态实验。它回答：

1. 本文方法是否不只是离线生成安全轨迹，还能在动态障碍进入未来风险区域时触发局部候选轨迹；
2. 与速度缩放、APF 反应式避障、MPC/APF、RRT 局部重规划相比，本文方法是否能获得更大的最小安全距离和更少的安全距离违规时间；
3. 由于完整 CCRO-NUBS 优化开销较大，本文应强调“风险触发式候选轨迹生成 + 高频安全滤波”，而不是每帧高频完整优化。

## E3.2 对比方法

| 方法 | 文献来源 | 实施方式 | 对比重点 |
|---|---|---|---|
| SSM / velocity scaling | ISO/TS 15066；Rosenstrauch et al., 2018 | 根据 D_min 分段降低速度或停止 | 只减速不改轨迹的局限 |
| APF reactive avoidance | Khatib, 1986 | 根据障碍距离产生排斥修正 | 反应式方法的安全裕度和抖动问题 |
| Cascaded MPC-APF style | Zhu et al., 2024 | 高层 APF/MPC 生成短时参考，低层跟踪与安全约束；可做核心思想复现 | 强动态避障基线 |
| RRT-Connect local replanning | Lee and Song, 2023；Shao et al., 2024 | 风险触发后在剩余路径上局部采样重规划并平滑 | 采样式局部重规划基线 |
| Ours CCRO-NUBS | 本文方法 | 时空风险触发 + 全身风险 + NUBS 候选轨迹 + dense safety check | 本文完整动态链路 |

## E3.3 场景设计

| 场景 | 描述 | 验证重点 |
|---|---|---|
| D1 远距离障碍 | 障碍物远离机器人和未来轨迹 | 不应误触发 |
| D2 末端动态干扰 | 障碍物接近末端执行路径 | 末端动态避障 |
| D3 本体动态干扰 | 障碍物接近中间连杆、肘部或小臂 | 全身动态避障 |
| D4 突然近距离进入 | 障碍物快速进入停止距离 | 安全接管和低风险恢复 |

建议每个场景 10–20 次。障碍物速度先设置为一个中速，例如 0.2 m/s；时间允许时再做 0.1/0.3 m/s 的速度敏感性分析，不作为必须新增实验。

## E3.4 虚拟闭环流程

每次实验按以下流程运行：

1. 使用同一初始 NUBS 轨迹作为参考执行轨迹。
2. 虚拟闭环按固定控制周期推进机器人状态。
3. 动态障碍按照预设速度进入场景。
4. 每个控制周期计算当前 `D_min`、预测风险和触发状态。
5. 对 SSM/APF/MPC/RRT/Ours 分别执行对应避障策略。
6. 对 Ours，当风险进入重规划区时调用 CCRO-NUBS 生成候选轨迹；候选轨迹通过 dense safety check 后才允许切换。
7. 若 `D_min` 小于停止阈值，则进入 safety hold，并记录恢复时间。
8. 实验结束条件为到达目标、发生安全违规、超过最大执行时间或进入不可恢复停止状态。

## E3.5 记录指标

| 指标 | 含义 |
|---|---|
| avoid success rate | 是否避障并到达目标 |
| D_min | 动态执行全过程最小安全距离 |
| T_viol | D_min 低于安全阈值的累计时间 |
| N_replan | 重规划触发次数 |
| replan accepted rate | 候选轨迹通过率 |
| T_replan | 单次重规划耗时 |
| task delay | 相比无障碍执行增加时间 |
| stop count | 安全保持次数 |
| jerk peak | 动作是否出现剧烈变化 |
| goal_error | 最终目标误差 |

## E3.6 预期结果

| 方法 | 预期现象 |
|---|---|
| SSM / velocity scaling | 可以降低风险，但因为不改变路径，可能导致任务停顿或在障碍持续存在时无法绕行 |
| APF reactive | 反应快，但在中间连杆近场和复杂动态场景中安全裕度有限，可能出现抖动 |
| Cascaded MPC-APF style | 是较强对比，若实现得当，可能在部分动态场景表现较好；结果需要客观比较 |
| RRT-Connect local replanning | 能找到绕障路径，但耗时、平滑性和验收通过率可能波动 |
| Ours CCRO-NUBS | 通过时空风险触发和全身风险验收，在 D2/D3 中应保持更大的 D_min，并减少 T_viol |

```text
本文方法能够在动态障碍进入未来轨迹区域时提前触发风险响应，通过局部候选轨迹生成和安全滤波提高最小安全距离，减少安全距离违规时间，并保持目标到达能力。
```

# E4 真实 RGB-D 与低速系统验证

## E4.1 实验目的

E4 不做大规模外部算法 benchmark，主要验证真实系统链路：

1. 真实 RGB-D 点云下能否完成机器人自滤除和外部障碍物提取；
2. 障碍物靠近非末端连杆时，本文全身风险是否比 critical-point/APF 风险响应更充分；
3. 候选轨迹是否经过 dense safety check、关节约束和目标误差验收；
4. 在低速条件下能否完成安全门控、减速/保持和可控执行。

如果没有稳定完成动态实机轨迹切换，不要写成完整实机在线重规划闭环。

## E4.2 对比方法

真实实验只建议保留两个对比：

| 方法 | 来源 | 作用 |
|---|---|---|
| Critical-point APF risk | Zhu et al., 2024；Khatib, 1986 | 代表已有关键点/人工势场避障思路 |
| Ours full-body spatiotemporal risk | 本文方法 | 验证 Mesh 全身采样与时空风险在真实点云下的响应 |

不建议在真实机械臂上完整复现 CHOMP、TrajOpt、GPMP2、RRT、MPC 等所有方法。真实实验的主要价值是系统链路验证，而不是外部算法排名。

## E4.3 实验层次与场景设计

E4 分为三个必须层次和一个可选增强层次：

| 层次 | 内容 | 是否必须 |
|---|---|---|
| E4-A | 真实 RGB-D shadow-mode 风险响应 | 必须 |
| E4-B | 低速无障碍/静态障碍轨迹执行 | 必须 |
| E4-C | 低速动态障碍安全门控 | 必须 |
| E4-D | 低速动态候选轨迹切换 | 可选增强 |

具体场景：

| 场景 | 内容 | 目的 |
|---|---|---|
| Real-1 中间连杆近场 | 手持轻质障碍物靠近大臂或小臂 | 验证非末端风险响应 |
| Real-2 动态接近与离开 | 障碍物缓慢靠近再远离 | 验证风险上升和恢复 |
| Real-3 低速安全门控 | 机械臂低速执行参考轨迹，障碍物进入近场 | 验证减速/保持 |
| Real-4 静态障碍 CCRO-NUBS 低速执行 | 执行已通过验收的风险约束轨迹 | 验证规划轨迹可执行性 |

## 七、实施优先级与风险控制

### 7.1 必须完成

| 方法/实验 | 原因 |
|---|---|
| Current-frame occupancy / Critical-point APF / Ours risk | 支撑时空风险与全身风险必要性 |
| RRT-Connect + smoothing | 最常用采样式基线 |
| CHOMP 或 TrajOpt 至少一个 | 经典优化式轨迹规划基线 |
| GPMP2 | 连续时间轨迹优化强基线 |
| SSM / velocity scaling | 工业安全基线 |
| APF reactive | 反应式避障基线 |
| 真实 RGB-D + Ours full-body risk | 证明真实链路可运行 |

### 7.2 尽量完成

| 方法/实验 | 原因 |
|---|---|
| CHOMP 与 TrajOpt 都做 | 提升 benchmark 完整性 |
| OctoMap-like occupancy | 占据建图类对比更完整 |
| MINCO-style / polynomial optimization | 与 NUBS 连续轨迹优化进行更贴近对比 |
| Cascaded MPC-APF style | 动态避障强基线 |
| RRT-Connect local replanning | 对应在线局部重规划已发表成果 |

### 7.3 可不做或放补充

| 方法/实验 | 原因 |
|---|---|
| RRT*、PRM | 高维机械臂下计算量大，对本文主线帮助有限 |
| STOMP | 可作为补充，但不是必须 |
| DRAFTO/FACTO 完整复现 | 很强但实现成本高，容易让论文焦点变成通用优化器排名 |
| 真实实机完整动态在线轨迹切换 | 风险和工程成本较高，可作为增强实验，不作为最低完成项 |

## 九、写作边界提醒

1. 主要对比实验写“本文方法 vs 已发表/已有方法”，不要写成“本文方法 vs 自己拆出来的弱版本”。
2. `NUBS-base`、`EEF-only`、`Body-current`、`w/o temporal prediction` 等内部方法只放在消融中。
3. MINCO-style 如果表现较好，应客观说明“风险约束对连续轨迹优化普遍有效”，不要写成 NUBS 全面优于 MINCO。
4. Cascaded MPC-APF 如果只实现核心思想版本，要在论文中写清楚是 “MPC-APF-style baseline”，避免声称完整复现原论文。
5. 真实实验主要验证链路可运行和低速安全，不要把真实 RGB-D shadow-mode 写成完整高频实机在线重规划。
6. CCRO-NUBS 完整优化耗时较大，应定位为触发式低频候选轨迹生成模块，高频安全由风险监测、速度缩放和安全滤波承担。

## 十、最终一句话

本实验路线的核心不是增加实验，而是将少数关键实验做扎实：

```text
用 E1 证明风险模型必要，用 E2 证明外部规划 benchmark 下 CCRO-NUBS 的安全平滑性，用 E3 证明动态重规划有效，用 E4 证明真实链路可运行，用 E5 解释模块贡献和计算边界。
```
