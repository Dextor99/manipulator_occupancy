# E1–E5 实验实施规划：基于 `manipulator_occupancy` 项目现有实现的复用与补充方案

> 本文档用于在已经明确 E1–E5 实验框架后，进一步落实每组实验的实施过程。重点不是重新设计实验，而是判断现有项目中哪些程序和结果可以复用，哪些结果只能作为消融或补充，哪些实验量不足需要补跑，哪些外部对比方法仍需新增实现。
>
> 项目地址：`https://github.com/Dextor99/manipulator_occupancy.git`

---

## 0. 总体判断

`manipulator_occupancy` 项目已经具备比较完整的实验链路，内容不再只是原型验证。项目中已经包含感知、风险、规划、控制、实验脚本和结果汇总等模块，整体覆盖了：

```text
RGB-D 点云感知
→ 机器人自滤除
→ 外部障碍物聚类与对象级建模
→ 障碍物运动预测
→ 构型耦合全身风险评价
→ NUBS / MINCO / RRT 轨迹规划
→ 虚拟闭环控制
→ 安全门控与真实 RGB-D replay
```

因此，后续实验不需要从零开始，而应按以下原则推进：

```text
E1、E2、E3、E4、E5 均已有部分可复用结果；
但现有结果不能全部直接写入论文；
需要按“外部对比主实验 + 内部消融补充”的逻辑重新筛选、补跑和整理。
```

当前最重要的调整是：

1. 外部对比实验应尽量采用已发表论文或成熟框架中的代表性方法；
2. `EEF-only`、`Body-current`、`NUBS-base`、`ee_only`、`ours_scale`、`ours_rep` 等内部变体应主要放在消融实验中；
3. 真实实验目前更适合表述为真实 RGB-D replay、shadow-mode、readiness gate 和低速安全验证，不宜直接写成完整真实机械臂动态在线轨迹切换。

# E1：风险感知与全身风险评价实验

## 1. 实验目标

E1 负责验证两个核心问题：

```text
1. 对象级时空风险是否比当前帧占据或普通体素占据更适合动态障碍预警；
2. Mesh 全身风险是否比末端距离或少量 critical points 更能覆盖机械臂本体风险。
```

E1 不应写成大规模点云感知 benchmark，而应围绕“时空风险”和“全身风险”形成集中证据。

---

## 3. 当前不足

E1 当前最大不足有两点。

### 3.1 全身风险对比仍偏内部变体

`exp_63_sim_risk_distance.py` 中的 `EEF-only` 和 `Body-current` 更适合作为消融或辅助分析，而不是主要外部对比。

最终论文主对比应尽量采用：

```text
Current-frame occupancy
OctoMap-like occupancy
Critical-point APF risk
Ours CCRO risk
```

其中 `Critical-point APF risk` 是当前缺失的外部风格风险评价基线，应补充实现。

### 3.2 实验量略小

`exp_62_sim_occupancy_risk.py` 默认 trial 数偏少。已有结果趋势可用，但论文正式结果建议补跑到：

```text
每类场景 10–20 次
```

建议主场景 `approach` 和 `crossing` 至少补到 20 次。

E2 应是外部规划方法对比的主要部分，但不应做成无边界的大规模规划器排名。

E2 当前缺少经典轨迹优化基线：


优先级建议：

```text
必须：RRT-Connect + smoothing

建议：GPMP2
增强：MINCO-style / polynomial optimization
```

# E3：动态障碍虚拟闭环与滚动重规划

E3 是第六章最核心实验。它验证：

```text
动态障碍进入未来轨迹区域时，本文方法能否通过时空风险触发、局部候选轨迹生成、轨迹验收和安全滤波提高安全裕度。
```

E3 不再比较静态规划器，而是比较动态响应策略。

## 3. 当前不足

E3 当前主要对比是：


# E4：真实 RGB-D 与低速系统验证

## 1. 实验目标

E4 不是外部算法大规模 benchmark，而是验证真实系统链路：

```text
真实 RGB-D 点云输入
→ 外部障碍物提取
→ 全身风险响应
→ 候选轨迹验收
→ 低速安全执行或安全门控
```

E4 的写作边界必须谨慎。如果未完成真实机械臂动态在线轨迹切换，不应声称完整实机在线重规划闭环。

---

## 2. 现有程序和结果可复用内容

### 2.1 真实系统汇总

# 关键写作边界

1. `EEF-only`、`Body-current`、`NUBS-base`、`ee_only`、`ours_scale`、`ours_rep` 等不应放在主要外部对比表中，应统一归入消融或内部模块贡献分析。
2. MINCO-risk 如果表现较好，应客观说明“风险约束对连续轨迹优化普遍有效”，不要写成 NUBS 全面优于 MINCO。
3. Cascaded MPC-APF 如果只实现核心思想版本，应写成 “MPC-APF-style baseline”，避免声称完整复现原论文。
4. 真实实验若只完成 replay、shadow-mode 和 readiness gate，不能写成完整真实机械臂动态在线重规划闭环。
5. CCRO-NUBS 完整优化耗时较高时，应定位为风险触发式低频候选轨迹生成模块，高频安全由风险监测、速度缩放和安全滤波承担。

```text
仿真和虚拟闭环实验验证时空风险、全身风险、风险约束 NUBS 和滚动重规划的有效性；
```
