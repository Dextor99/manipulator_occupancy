# CCRO-NUBS P6：统一基线、消融与灵敏度实施计划

## 1. 目标

将已有证据按同一问题维度整理，而不是把不同场景的数字混成单一排名：

1. 轨迹表示：单段五次最小 jerk、NUBS fixed-T、NUBS variable-T；
2. 空间风险：无风险、仅末端、全身 Mesh；
3. 时间风险：当前帧、末端时空、全身时空；
4. 系统层级：A4 单次规划、A5 异步重规划、A6 安全执行层；
5. 灵敏度：`lambda_time=[0.02,0.05,0.10,0.20]`。

## 2. 公平性规则

- 同一子表只比较相同场景、几何密度、距离门槛和随机 trial；
- P1 的 medium 统计不替代阶段 2/3 dense 名义验收；
- P5 同时报告 dense 可行、严格收敛和超时；
- 不把项目内近似基线写成对外论文官方实现；RRT-Connect/MINCO 若后续加入，必须锁定版本、参数、碰撞模型和时间参数化。

## 3. 自动程序

`experiments/exp_ccro_p6.py` 从 P1/P2/P4/P5 的冻结 JSON 生成统一表，并重新运行时间权重扫描。单段五次边界轨迹由同一 NUBS 后端在 `piece_count=1` 时计算，作为无中间自由度的 minimum-jerk 表示基线。

## 4. 验收

所有冻结来源的对应仿真验收必须通过；权重扫描全部正常收敛、时间有界、边界/限位通过。输出必须携带来源路径，禁止手工抄数。

## 5. 运行

```bash
bash scripts/setup_ccro_p6.sh
```

输出包括 `metrics.json`、`table_p6.md`、`lambda_time_sweep.jsonl`。真实真值缺口仍引用 P3，不因统一表生成而自动消失。

## 6. 实际执行结果（2026-06-23）

所有冻结仿真来源通过，时间权重扫描 `4/4` 收敛：

| lambda_time | duration / s | jerk energy |
|---:|---:|---:|
| 0.02 | 7.17424 | 0.02869696 |
| 0.05 | 6.15818 | 0.06158182 |
| 0.10 | 5.48632 | 0.10972633 |
| 0.20 | 4.88775 | 0.19551009 |

结果呈现清晰的时间—平滑度 Pareto 关系。无障碍情况下单段 quintic 与优化后的 fixed-T NUBS jerk 能量相同，说明 NUBS 额外自由度的价值主要体现在风险/约束条件下，而不是无条件降低理论 minimum-jerk 能量。
