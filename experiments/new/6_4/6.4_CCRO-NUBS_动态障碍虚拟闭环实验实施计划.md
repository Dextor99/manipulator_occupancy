### 0.1 G0：正式实验前一致性审计

正式全集启动前必须先运行：

```bash
conda run --no-capture-output -n py310 python -u -m experiments.new.6_4.g0_audit_64 \
  --output results/new/6_4_final_gate/mechanism_d1
```

G0 审计回答五个问题：

1. 优化风险项、候选在线验收、reference 验收、bridge 检查和 GT 复核的距离定义是否一致；
2. 候选轨迹 \(q_{\mathrm{cand}}(\tau)\) 是否对应 \(\hat{o}(t_{\mathrm{switch}}+\tau)\)，而不是错误对应触发时刻；
3. bridge 段和 candidate 段的最小距离是否被分开统计；
4. medium 在线检查和 dense GT 复核的最小距离误差是否可接受；
5. 候选漏斗是否能区分 finished、within-budget、continuity、online-safe、beneficial、switched 和 GT-safe。

若 G0 显示候选在 submission 时安全、但 switch 时系统性失败，则不得继续通过放宽 `D_ONLINE_ACCEPT` 或改场景来制造成功率，必须进入候选回放阶段定位时间轴与候选持久有效性问题。

### 0.2 正式对比方法重组

正式主表只保留三个闭环方法：

| 方法 | pending 阶段安全策略 | 候选规划 |
|---|---|---|
| SSM-only | 统一 SSM/APF 或减速-保持 | 无 |
| Critical-NUBS | 与其他方法相同 | 稀疏局部全身关键点 |
| CCRO-NUBS | 与其他方法相同 | Mesh 构型耦合全身风险 |

`Reference-only` 仅作为 pilot/counterfactual 风险下界，不作为主要闭环方法。三种正式方法必须共享触发器、pending 状态机、速度缩放、安全保持、优化预算、切换时刻和在线验收门控；Critical-NUBS 与 CCRO-NUBS 的主要差异只能是候选规划风险表示。

### 0.3 阶段 A：固定状态候选规划回放

阶段 A 不执行闭环机械臂，只在固定触发/切换状态上评估候选生成能力。推荐先运行 D1 smoke：

```bash
conda run --no-capture-output -n py310 python -u -m experiments.new.6_4.candidate_replay_64 \
  --output results/new/6_4_candidate_replay_d1_smoke \
  --scenario D1 \
  --smoke
```

评价指标包括：

- `planner_finished`；
- `within_budget`；
- `optimizer_converged`；
- `online_feasible`；
- `dense_feasible`；
- `continuity_pass`；
- `online_distance_pass`；
- `beneficial`；
- \(\Delta D_{\min}=D_{\min}^{candidate}-D_{\min}^{reference}\)。

速度和冲突提前量按能力边界网格组织：

| 因素 | 水平 |
|---|---|
| 障碍物速度 | 0.15, 0.25, 0.35 m/s |
| 冲突提前量 | Long 7.5 s, Medium 6.0 s, Short 4.5 s |
| 场景 | D1 body-crossing, D2 approach |

阶段 A 的目的不是证明闭环成功，而是先确认 CCRO-NUBS 是否比 Critical-NUBS 更容易生成在线和 dense 均可行、且相对 reference 有净空收益的候选轨迹。

### 0.5 2026-07-28 实时性重构：Fast CCRO-NUBS Local Repair

6.4 的正式在线算法改为 **Fast CCRO-NUBS local repair**，目标是验证毫秒级局部修复，而不是秒级完整 NUBS 非线性优化。

冻结工程目标：

| 环节 | P95 目标 |
|---|---:|
| 点云/对象更新 | 10--20 ms |
| CCRO 风险监测 | <= 10 ms |
| 快速局部修复 | 50--80 ms |
| 候选安全验收 | 20--40 ms |
| 端到端响应 | 100--150 ms |
| 极端最大耗时 | <= 200 ms |

新增入口：

```bash
conda run --no-capture-output -n py310 python -u -m experiments.new.6_4.fast_local_repair_64 \
  --output results/new/6_4_fast_local_repair_d1_smoke \
  --scenario D1 \
  --smoke
```

Fast local repair 的在线限制：

- 局部时域固定为 1.0 s；
- 时间分配和 knot span 固定，不联合优化时间；
- 只修复 3--5 个局部插值点；
- 每轮只针对当前最危险时间/连杆/风险点做修正；
- 最多 1--3 次快速修复；
- dense/medium Mesh 只用于候选终检；
- 若 100--150 ms 内未得到可用候选，则候选拒绝并交由安全层继续减速/保持。

主指标不再使用 `optimizer_converged`，而使用：

\[
R_{\mathrm{usable}}
=
R(
\text{ready before 150 ms}
\land
\text{dense geometry feasible}
).
\]

同时报告：

\[
T_{\mathrm{risk}},
T_{\mathrm{repair}},
T_{\mathrm{validation}},
T_{\mathrm{total}},
\Delta D_{\min}^{dense}.
\]

当前 D1 fast smoke 的初步结果表明：端到端耗时已经进入约 80--120 ms，但 dense feasible 仍为 0。这说明时间尺度已经转入实时范围，新的主要瓶颈是快速修复方向/幅度尚不足，而不是继续补偿秒级规划延迟。

### 0.6 Fast repair v2 与 G1 Go/No-Go

fast repair v2 做如下结构修正：

- 使用最小净空 \(D_{\min}\) 的 6 关节有限差分梯度，而不是风险代价梯度；
- 每轮尝试多个有限步长 \([0.008,0.015,0.025,0.035]\) rad；
- 只有当 medium Mesh 最小净空单调改善且位置/速度/加速度约束均满足时才接受更新；
- 在线 medium gate 与离线 dense GT recheck 分开计时；
- `usable_candidate` 定义为：

\[
\text{online latency}\le150\,\mathrm{ms}
\land
\text{online accepted}
\land
\text{dense GT safe}.
\]

G1 Easy 场景不再使用名义表面 clearance 直接决定难度，而是在生成后用公共 dense Mesh 筛选：

\[
0.04\le D_{\min,\mathrm{reference}}^{dense}<0.08.
\]

这保证 G1 是浅风险修复问题，而不是深穿透恢复问题，并且筛选条件不依赖 Critical 或 CCRO 的优化结果。

当前 G1 CCRO v2 诊断结果：

- G1 valid shallow-risk scenarios: 10/10；
- online P95 约 141 ms，max 约 142 ms；
- acceleration gate pass: 9/10；
- dense feasible: 0/10；
- usable candidate: 0/10；
- dense 净空改善中位数为 0，最大约 0.005 m。

因此 v2 尚未通过 G1。该结果说明实时延迟已经可控，但当前“有限差分方向 + 步长接受”的局部修复仍无法可靠恢复 0.08 m 全身净空。下一步不应继续提高固定步长或放宽阈值，而应升级为：

- 小规模 QP/SQP，对局部插值点直接施加线性化净空约束；
- 或加入最近 Mesh 点解析/自动微分 Jacobian；
- 并在每次更新中显式约束速度和加速度。

在 G1 达到 CCRO usable candidate \(\ge 8/10\) 前，不启动完整 fast Stage-A 或 Stage-B 闭环。

### 0.7 Fast CCRO-NUBS v3：局部顺序凸修复器

v3 的目标是把 v2 的“单方向梯度步”替换为第五章 CCRO 风险约束模型的在线局部凸化形式：

\[
d_i + A_i\Delta P \ge d_{\mathrm{safe}},
\]

其中 \(P\) 为 1 s 局部 NUBS 插值点，\(\Delta P\) 为待求解的局部修复增量。当前已新增模块：

```text
experiments/new/6_4/repair/
  active_distance.py
  nubs_linearization.py
  local_qp_solver.py
  repair_v3.py
```

当前 scaffold 版本包含：

- active distance extraction；
- 局部 NUBS 插值点有限差分敏感度；
- 安全 slack 约束；
- SLSQP-backed 小规模线性化修复；
- `ccro_fast_v3` / `critical_fast_v3` 方法入口；
- G1-near dense 筛选：

\[
0.07\le D_{\min,\mathrm{reference}}^{dense}<0.08.
\]

G1-near CCRO v3 scaffold 结果：

- valid near-risk scenarios: 10/10；
- dense feasible: 0/10；
- usable candidate: 0/10；
- acceleration gate pass: 9/10；
- online mean 约 123.5 ms；
- online P95 约 245.4 ms，超过 150 ms 目标；
- dense 净空改善中位数为 0，最大约 0.001 m。

因此当前 v3 是结构 scaffold，而不是最终 fast solver。后续应将临时的有限差分/SLSQP 实现替换为：

- OSQP 或等价毫秒级 QP solver；
- 最近 Mesh 点解析 Jacobian \( \partial d/\partial q = n^T J(q) \)；
- 更稳定的 active set，至少 Top-4 time × Top-2 points；
- 显式 trust region 与速度/加速度线性约束；
- 最多 2 次 sequential convex repair。

在该版本通过 G1-near 前，仍不得进入完整 fast Stage-A。

### 0.8 Fast CCRO-NUBS v4：active-set Jacobian QP scaffold

v4 按评审意见完成三项结构修改：

1. active set 从 risk top-k 改为 dense Mesh 最近点约束；
2. 距离梯度从 6 关节有限差分改为解析形式：

\[
\frac{\partial d}{\partial q}
=
n^TJ_{point}(q),
\]

其中 `URDFModel` 提供 joint origin/axis，`RobotSurfaceModel` 提供 link-local surface point translational Jacobian；

3. 修复步骤不再调用 SLSQP。当前环境未安装 OSQP，因此 v4 暂用 deterministic projected half-space QP fallback，保持线性约束 QP 接口，后续可直接替换为 OSQP。

G1-near CCRO v4 诊断结果：

- valid near-risk scenarios: 10/10；
- dense feasible: 0/10；
- usable candidate: 0/10；
- acceleration gate pass: 10/10；
- online mean 约 128.4 ms；
- online P95 约 183.2 ms；
- QP fallback median time 约 3.4 ms；
- dense 净空改善中位数为 0，最大约 0.00024 m。

因此 v4 已解决 SLSQP 依赖和解析 Jacobian 接口问题，但仍没有形成有效的全身净空恢复能力。当前剩余 blocker 不再是 QP 求解耗时，而是：

- dense active set 对真实 \(D_{\min}\) 的线性化有效性不足；
- 1 s 局部 NUBS 内部插值点自由度可能不足；
- trust-region 内的 \(\Delta P\) 无法在不破坏动态约束的情况下产生 1--2 cm 级全身净空提升。

下一步若继续推进，应优先做单实例几何单元测试：

- 固定一个 G1-near 样本；
- 输出 active dense 点、\(n^TJ\)、\(B(t)\)、预测净空提升和实际 dense 净空提升；
- 验证线性模型是否有符号错误、尺度错误或 active point 切换问题；
- 通过该单实例后，再接入 OSQP 并重跑 G1-near 10 例。

在单实例线性化审计通过前，不再运行完整 Stage-A 或 Stage-B。

在 Fast local repair 达到例如 \(T_{\mathrm{total}}^{P95}<100\text{--}150\,\mathrm{ms}\) 且 G1/Stage-A 成立前，论文不得使用以下表述：

- real-time trajectory replanning；
- real-time safe motion generation；
- online dynamic obstacle avoidance planning；
- applicable to real-time safe operation。

当前允许的表述为：

- risk-triggered candidate trajectory generation；
- low-frequency trajectory repair；
- asynchronous replanning under safety supervision；
- fast local repair prototype。

## 1. 实验定位

建议将第 6.4 节标题确定为：

> **6.4 动态障碍下异步局部重规划的闭环有效性与能力边界实验**

本节采用**软件虚拟闭环实验**，不直接驱动真实机械臂。机械臂状态、动态障碍物运动、风险监测、速度缩放、候选轨迹生成、轨迹验收和轨迹切换均在离散控制循环中完成。真实 RGB-D 感知与低速实机验证继续安排在第 6.5 节。

本节重点验证以下问题：

1. 动态障碍即将进入参考轨迹风险区域时，系统能否正确提前触发重规划；
2. 规划线程运行期间，机械臂能否减速继续执行，而不是暂停等待规划结果；
3. 候选 CCRO-NUBS 轨迹能否通过连续性、关节运动约束和密集安全验收，并在计划切换时刻完成轨迹替换；
4. 无风险场景能否避免误触发，初始高风险场景能否及时进入安全保持。

现有 `exp_ccro_stage4.py` 中已经包含动态风险评价、异步重规划管理、轨迹缓冲、动态 NUBS 优化和候选轨迹验收等基础组件。新版 6.4 应复用这些核心模块，并重新组织为统一的统计性虚拟闭环实验。

### 2.1 正式对比方法

主实验保留三种方法：

| 方法 | 风险监测 | 速度缩放 | 轨迹重规划 | 安全保持 |
|---|---:|---:|---:|---:|
| Reference-only | 否 | 否 | 否 | 否 |
| SSM | 当前全身最小距离 | 是 | 否 | 是 |
| CCRO-NUBS | STRO 未来占据 + CCRO | 是 | 是 | 是 |

#### Reference-only

机械臂始终沿原始 NUBS 参考轨迹执行，不执行速度缩放、重规划和安全保持。该方法作为反事实基线，用于判断原参考轨迹在动态障碍条件下是否会进入安全距离违规区。

当真实最小距离首次低于安全阈值时，可判定该次试验失败并终止，避免继续模拟几何穿透。

#### SSM

根据当前构型下的全身最小距离进行速度缩放和安全保持，但不改变原始轨迹的空间形状。

该方法用于验证：

> 仅依靠减速或停止，是否能够同时保证安全并完成任务。

#### CCRO-NUBS

根据对象级未来占据评价当前参考轨迹。进入中风险区后，机械臂减速并异步生成候选剩余轨迹；候选轨迹通过密集安全验收后，在计划切换时刻替换原参考轨迹；当前风险进入高风险区时执行安全保持。

其完整流程为：

\[
	ext{未来风险预测}
ightarrow
	ext{减速并触发重规划}
ightarrow
	ext{异步候选生成}
ightarrow
	ext{密集安全验收}
ightarrow
	ext{轨迹切换或安全保持}.
\]

APF 不建议纳入第 6.4 节主表。速度级 APF 与异步连续轨迹重规划属于不同技术层次，更适合放在第 6.6 节的模块消融或安全执行分析中。

## 3. 正式实验场景

### 3.1 D1：中间连杆动态横穿

障碍物从上臂、肘部或前臂附近横穿原始参考轨迹的扫掠空间。

障碍物初始位置保持安全，但根据未来运动预测，原始参考轨迹会在后续时刻进入风险区。

设置三档障碍物速度：

\[
v_o \in \{0.06,\ 0.09,\ 0.12\}\ \mathrm{m/s}.
\]

每档生成 5 个预先固定的扰动实例，共 15 个实例。

扰动内容包括：

- 障碍物初始中心：各坐标轴扰动范围为 \(\pm 0.02\ \mathrm m\)；
- 横穿方向：标称方向扰动范围为 \(\pm 5^\circ\)；
- 障碍物速度：标称值上下扰动 5%；
- 障碍物半径：0.04–0.06 m；
- 目标风险区域：上臂、肘部和前臂均衡分布。

验证重点：

- 非末端未来风险是否能够正确触发；
- SSM 是否因持续阻塞而只能减速或停止；
- CCRO-NUBS 是否能够绕开中间连杆风险并完成目标。

### 3.2 D2：末端动态横穿

障碍物横穿腕部、夹爪或末端执行器运动区域。

速度档位和重复次数与 D1 一致：

\[
3\ 	ext{档速度}	imes 5\ 	ext{个实例}=15\ 	ext{个实例}.
\]

验证重点：

- 末端区域未来风险是否正确触发；
- 候选轨迹接受率；
- 障碍物速度升高后安全裕度是否下降；
- 轨迹切换后是否能够完成目标。

### 3.3 D3：远距离安全场景

生成 10 个障碍物始终远离参考轨迹的实例。

验证内容：

- 是否出现错误风险触发；
- 是否提交不必要的重规划；
- 是否能够正常完成原任务。

期望结果：

\[
N_{\mathrm{false\ replan}}=0.
\]

## 4. 场景生成与筛选

### 4.1 真值运动与观测运动分离

观测障碍物用于风险触发和轨迹规划：

```text

observed_velocity
observed_radius
```

建议加入以下误差：

- 位置噪声：\(\sigma_p=0.005\ \mathrm m\)；
- 速度噪声：\(\sigma_v=0.01\ \mathrm{m/s}\)；

D1 和 D2 实例应同时满足：

1. 初始真值距离大于 0.16 m；
2. 原参考轨迹在未来时刻存在风险；
3. 原参考轨迹的最小真值距离位于 0.03–0.075 m；
4. 初始时刻不存在几何穿透；
5. 高预算 CCRO-NUBS 能够找到满足 0.08 m 验收距离的候选轨迹；

筛选完成后，应固定随机种子和所有场景参数，后续所有方法必须使用完全相同的实例。

## 8. 虚拟闭环执行过程

### 8.1 每个控制周期的执行顺序

在每个控制周期 \(t_k\) 内，依次执行以下步骤。

#### 步骤 1：更新 GT 障碍物

\[
p_{\mathrm{gt}}(t_k)
=
p_0+v_{\mathrm{gt}}t_k.
\]

根据 GT 障碍物和当前机械臂构型计算：

\[
D_{\mathrm{cur}}^{\mathrm{GT}}.
\]

该距离仅用于记录，不反馈给任何方法。

#### 步骤 2：更新障碍物观测

按照 30 Hz 更新带噪障碍物中心、速度和半径。

在两个观测周期之间保持上一帧观测状态。

#### 步骤 3：构建未来占据

根据观测中心和观测速度构建未来风险占据。

风险触发和候选轨迹规划全部使用该观测预测结果。

#### 步骤 4：采样当前活动轨迹

从 `TrajectoryBuffer` 中获得：

\[
q(t_k),\quad \dot q(t_k),\quad \ddot q(t_k).
\]

#### 步骤 5：评价当前和未来风险

计算当前观测距离：

\[
D_{\mathrm{cur}}^{\mathrm{obs}}
\]

以及未来参考轨迹窗口内的最小距离：

\[
D_H^{\mathrm{obs}}.
\]

风险状态划分为：

- LOW：继续执行；
- MEDIUM：减速并触发候选轨迹生成；
- HIGH：安全保持。

#### 步骤 6：速度缩放

SSM 和 CCRO-NUBS 使用：

\[
lpha(D)=
egin{cases}
0, & D\le d_{\mathrm{stop}},\
\dfrac{D-d_{\mathrm{stop}}}
{d_{\mathrm{slow}}-d_{\mathrm{stop}}},
& d_{\mathrm{stop}}<D<d_{\mathrm{slow}},\
1, & D\ge d_{\mathrm{slow}}.
\end{cases}
\]

轨迹时钟更新为：

\[
	au_{k+1}
=
	au_k+lpha(D_{\mathrm{cur}}^{\mathrm{obs}})\Delta t.
\]

这样，规划期间机械臂会减速继续执行，而不是暂停等待规划结果。

#### 步骤 7：异步提交候选轨迹

当满足：

\[
D_H^{\mathrm{obs}}<d_{\mathrm{replan}}^{\mathrm{in}}
\]

且当前没有正在运行的规划任务时，提交候选轨迹。

计划切换时刻为：

\[
t_s=t_k+\Delta_s.
\]

候选轨迹起点边界取原参考轨迹在 \(t_s\) 的：

\[
q(t_s),\quad \dot q(t_s),\quad \ddot q(t_s).
\]

#### 步骤 8：规划期间继续执行

规划线程运行期间：

- 原活动轨迹继续执行；
- 速度根据当前风险距离缩放；
- 持续监测当前风险；
- 若进入停止区，则立即中止候选轨迹并执行安全保持。

#### 步骤 9：候选轨迹验收

候选轨迹完成后依次检查：

1. 规划是否在计划切换时刻前完成；
2. 数值结果是否有效；
3. 切换点位置连续性；
4. 切换点速度连续性；
5. 切换点加速度连续性；
6. 终端目标误差；
7. 关节位置限制；
8. 关节速度限制；
9. 关节加速度限制；
10. 基于观测预测占据的 dense 最小距离：

\[
D_{\min}^{\mathrm{val}}\ge0.08\ \mathrm m.
\]

只有全部通过后，候选轨迹才能替换原参考轨迹。

#### 步骤 10：轨迹切换

验收通过后：

- 在 \(t_s\) 激活候选轨迹；
- 替换原参考轨迹的后续执行段；
- 记录轨迹切换事件；
- 继续闭环风险监测。

验收失败时：

- 保留当前活动轨迹；
- 继续减速执行；
- 满足重试间隔后允许再次规划；
- 若进入停止区，则执行安全保持。

## 9. 试验终止条件

一次试验满足任一条件即结束：

1. 达到目标：
   \[
   \|q_{\mathrm{final}}-q_{\mathrm{goal}}\|
   \le
   \epsilon_{\mathrm{goal}};
   \]
2. GT 安全距离低于 0，出现几何穿透；
3. 超过最大试验时长；
4. 安全保持持续超过设定时间且障碍物未离开；
5. 预测时域失效；
6. 出现数值异常。

Reference-only 在首次进入 GT 安全距离违规区后即可判定失败并结束。

该实施方案与当前项目已有的异步重规划、轨迹缓冲、动态风险评价和密集候选验收逻辑一致，可将第 6.4 节从功能性案例提升为可用于论文的统计性动态虚拟闭环实验。

## 15. 最新定型约束：Fast CCRO-NUBS v4

根据最近一轮审计，6.4 的正式路径不再使用秒级异步全局候选优化作为实时方法证明。当前保留两层结论：

- 秒级异步 CCRO-NUBS：只作为诊断材料或能力边界讨论；
- Fast CCRO-NUBS v4：作为实时动态局部修复的候选方法，但必须先通过 G1/G1-near 门控。

v4 的新增实验设计约束如下：

- G1/G1-near 风险必须落在局部段内部可控窗口，不允许由固定头尾端点主导；
- G1/G1-near 样本必须通过 dense active-set 可控性过滤；
- 点雅可比、NUBS 灵敏度和 QP 预测增益必须先经单实例审计；
- 在线 v4 路径限制为 1 次 QP；
- QP 目标 clearance 为 0.095 m；
- 在线接受阈值仍为 0.09 m，dense GT 安全阈值仍为 0.08 m；
- 步长接受必须通过 0.04 s 运动学采样，避免 0.10 s repair 采样漏检加速度峰值。

最新 G1-near 结果：

- 审计结果：`results/new/6_4_v4_linearization_audit_d1_00_controllable/paper/table_6_4_v4_linearization_audit.md`；
- G1-near 小批量结果：`results/new/6_4_fast_local_repair_g1_near_ccro_v4_controllable_target095/paper/table_6_4_fast_local_repair.md`；
- dense geometry feasible：10/10；
- acceleration gate：10/10；
- hard realtime：10/10；
- online P95：约 136.1 ms；
- usable candidate：5/10；
- 平均 dense clearance 提升：约 0.0125 m。

因此，当前版本可以支撑论文中“从秒级候选优化转向快速局部约束修复”的方法演进和 G1 能力边界分析，但还不能作为正式全集验收通过结果。下一步只有在不修改外层机制和验收阈值的前提下，使 G1/G1-near 的 online acceptance 稳定达到预设门槛，才允许进入正式 Stage-A/Stage-F。
